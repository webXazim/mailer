Getting started

Send your first email

Signal Mail gives your application a reliable HTTP API for transactional email, delivery events, and domain-level controls.

In production, use a dedicated API key and a verified sending domain. Test keys can only deliver to approved recipients.

1. Authenticate your request

Pass your API key as a bearer token. Keys are created in your workspace under API keys.

bash
curl https://api.signalmail.dev/v1/emails \
  -H "Authorization: Bearer sk_live_your_key" \
  -H "Content-Type: application/json"

2. Send an email

Send a JSON payload with a verified sender, one or more recipients, and your message content.

curl
curl https://api.signalmail.dev/v1/emails \
  -H "Authorization: Bearer $SIGNALMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "Acme Cloud <hello@mail.acme.dev>",
    "to": ["jordan@northstar.io"],
    "subject": "Welcome to Acme Cloud",
    "html": "<h1>Welcome, Jordan</h1>"
  }'

3. Verify your domain

Add the SPF and DKIM records shown in your workspace under Domains. Once DNS is visible, Signal Mail verifies the records automatically.

01Add your domain

Open Domains and enter the domain or sending subdomain you control.

02Publish DNS records

Add the generated TXT and CNAME records at your DNS provider.

03Check verification

Return to Signal Mail and select Check records.

4. Receive delivery events

Configure a webhook endpoint to receive signed events such as email.delivered, email.bounced, and email.delivery_delayed.

event payload
{
  "type": "email.delivered",
  "id": "evt_01H9K8D4QW",
  "data": { "email_id": "msg_01H9K8D4QW" }
}

Error handling

Errors return a stable code, a human-readable message, and a request ID for support and debugging.

StatusCodeMeaning
401invalid_api_keyAuthentication failed or the key was revoked.
422invalid_requestA required field is missing or malformed.
429rate_limitedRetry after the interval returned in the response headers.
